# NOTE4C Codex 用量监控 — 完整实施方案

> 2026-11-25 · 状态：管道已验证跑通（首图已上屏），本方案定义正式化改造

## 一、目标

把 Mac 上已有的 Codex 用量监控（三渠道：Codex 本地 / 飞书 / 企业微信）常显在 NOTE4C 四色墨水屏上：**桌面摆一块屏，抬头看用量与健康状态，无需开电脑页面。**

## 二、系统架构

```
┌─────────────────────┐
│ 数据层（已有，不动）  │  http://127.0.0.1:18741/api/snapshot
│ Python 监控服务      │  每 5s 自刷新，含三渠道用量+连接状态
└──────────┬──────────┘
           ↓ 只读拉取
┌─────────────────────┐
│ 渲染层 render_codex.py│  Pillow 画 400×300 四色面板
│                      │  → 2bpp 原始像素打包（30000 字节）
└──────────┬──────────┘
           ↓ HTTP POST /upload（+ /photo/show 自动显示*）
┌─────────────────────┐
│ 显示层 NOTE4C        │  墨水屏常显，断电保持画面
│ v6.5.9 固件          │  局域网服务开启时不休眠
└─────────────────────┘
        (* 需升级固件，见 Phase 2)
```

**设计原则**：监控服务和网页一行代码不动，渲染器只是它的第二个只读客户端；屏幕只放摘要，细节回网页看。

## 三、分层细节

### 1. 渲染层（增强现有 render_codex.py）

- **布局**（已验证）：黑标题栏 / 2×2 卡片（三渠道+今日合计）/ 底部黄条（数据时间+渲染时间）
- **颜色语义**：黑=连接正常 · 黄=状态待确认 · 红=进程离线告警
- **新增：数据变化检测**——对渲染输入计算 hash，与上次相同则跳过推送。理由：墨水屏全刷有机械寿命，无变化硬刷纯损耗；用量数据低频变化，30 分钟粒度足够
- **新增：容错页**——监控服务拉不到时，渲染红色「监控服务离线」告警页推上去（屏幕本身变成服务健康探针）

### 2. 推送层

- 当前固件：`POST /upload?format=bwry2bpp` → 图进相册
- **相册清理**：每次推送成功后 `DELETE /photo?id=<上次id>`，相册只保留最新一张，避免堆积
- **IP 管理**：配置文件记住设备 IP；失联时自动子网扫描重发现，仍失败则记日志退出（设备可能休眠/离网）
- 已知限制：v6.5.9 固件无 `/photo/show`，推图后需回相册查看 → Phase 2 解决

### 3. 调度层（launchd）

- `com.hunter.note4c-codex-push.plist`，`StartInterval=1800`（每 30 分钟）
- Mac 睡眠/关机时天然不推，唤醒后下一周期恢复
- 日志落 `note4c-push.log`（时间、成功/失败、跳过原因）

### 4. 数据层依赖

- 监控服务必须常驻（它已经是常驻服务）
- ⚠️ 待查：11-25 13:27 快照三渠道全为 0（21 号还有 91.5M）——需确认监控服务数据源状态，这不影响本方案结构，但影响屏上有没有数

## 四、实施阶段

### Phase 1：自动化闭环（用现有固件，今天可完成）
1. render_codex.py 增强：hash 去重、容错告警页、相册清理、IP 重发现
2. 安装 launchd 定时任务（30 分钟）
3. 验收：改一条监控数据 → 30 分钟内屏上图更新；停掉监控服务 → 屏变红色离线告警

### Phase 2：自动刷新显示（推荐，刷机 1 分钟）
1. 刷 11 月新版 Demo 固件（或社区 v6.6.3.1，含黑黄快刷/局部刷新/农历）
2. 获得 `/photo/show`：推图后屏幕**自动刷新显示**，真正无人值守
3. 收益：不用回相册手动翻；风险：已备份全量 Flash，可随时还原

### Phase 3：增强（按需）
- **变化即推**：本地 1 分钟轮询 snapshot，hash 变化立即推（状态离线 1 分钟内上屏），推图频次自适应
- **多页轮播**：用量页 + 明细页 + 告警页，利用固件 slideshow 定时轮换
- **语音便签**：设备麦克风录音 → DashScope ASR → 文字入监控/TAPD（硬件麦克风闲着也是闲着）

## 五、风险与对策

| 风险 | 对策 |
|------|------|
| 墨水屏刷新寿命 | hash 去重，无变化不刷；30min 粒度 ≈ 48 刷/天，远在寿命内 |
| 设备 DHCP 换 IP | 配置记忆 + 自动扫描；根治方案：路由器绑定静态 IP |
| Mac 休眠期间数据过期 | 墨水屏断电保持最后画面，只是「旧」不是「错」；下次唤醒自动补推 |
| 监控服务自身故障 | 容错告警页把故障直接亮在屏上 |
| 刷机变砖 | 16MB 原厂备份 + 台账（flash-backup/BACKUP.md），可完整还原 |

## 六、验收标准

1. 屏上图与网页数据一致（同一 snapshot）
2. 30 分钟周期自动更新，Mac 唤醒后自动恢复
3. 监控服务停止 → 屏幕出现红色离线告警
4. 相册中始终只有最新一张图
